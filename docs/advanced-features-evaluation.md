# 乐理学习游戏 · 进阶功能方案评估

> **文档性质**：独立方案设计，不涉及现有 Demo 代码修改  
> **版本**：v1.0  
> **日期**：2026-06-26  
> **约束**：纯前端 · 单页 HTML · Tonal.js 乐理计算 · Web Audio 发声

---

## 1. 概述

### 1.1 背景

现有乐理练习 Demo 已具备**答题、连击、计分、难度选择、听音识名**等基础交互，适合作为「知识检验」层。本方案在**不改动现有代码**的前提下，独立评估三个进阶方向：

| 方向 | 核心能力 | 与 Demo 的关系 |
|------|----------|----------------|
| 方向一：键盘演奏练习 | 输入式演奏，强化音高/和弦肌肉记忆 | 从「选答案」延伸到「弹出来」 |
| 方向二：节奏闯关 | 下落式节奏判定，训练时值感 | 从「认节奏型」延伸到「打节奏」 |
| 方向三：乐理符号识别 | 翻翻乐/配对/拖拽，符号视觉记忆 | 从「文字题」延伸到「符号图鉴」 |

### 1.2 技术栈基线

| 层级 | 选型 | 说明 |
|------|------|------|
| 乐理计算 | [Tonal.js](https://github.com/tonaljs/tonal) | 音名解析、音程、和弦、音阶、转调；MIT 协议，~20KB gzip |
| 音频引擎 | Web Audio API | 浏览器原生，零依赖，适合振荡器与采样播放 |
| 采样音源（可选） | [WebAudioFont](https://github.com/surikov/WebAudioFont) | SoundFont 转 JS，钢琴/吉他/鼓组采样 |
| 渲染 | 原生 DOM + CSS / Canvas 2D | 单页 HTML 内完成，无需 React/Vue |
| 节奏谱面（可选） | 自制 JSON 谱面 或 [Magenta.js](https://github.com/magenta/magenta-js) 辅助 | 纯前端可手写简单谱面 |

### 1.3 评估维度说明

每个方向均从以下维度展开：

- **界面布局草图**（文字描述）
- **交互流程**
- **技术选型**
- **实现复杂度**（低 / 中 / 高）
- **与现有 Demo 的衔接方式**

## 2. 方向一：键盘演奏练习模块

### 2.1 功能目标

通过电脑键盘模拟**钢琴、吉他、架子鼓**三种乐器，用户按键即发声，配合视觉反馈，形成「演奏 → 听音 → 肌肉记忆」闭环。

### 2.2 界面布局草图（文字描述）

```
┌─────────────────────────────────────────────────────┐
│  [🎹 钢琴]  [🎸 吉他]  [🥁 架子鼓]     ← 乐器 Tab 切换  │
├─────────────────────────────────────────────────────┤
│                                                     │
│   ┌─ 钢琴模式 ─────────────────────────────────┐   │
│   │  [Oct -]  Octave: 4  [Oct +]   [♯/♭ 切换]  │   │
│   │                                              │   │
│   │  ┌──┬──┬──┬──┬──┬──┬──┬──┬──┬──┬──┬──┐      │   │
│   │  │C#│D#│  │F#│G#│A#│  │  ← 黑键行         │   │
│   │  ├──┼──┼──┼──┼──┼──┼──┼──┼──┼──┼──┤      │   │
│   │  │C │D │E │F │G │A │B │C │  ← 白键行       │   │
│   │  └──┴──┴──┴──┴──┴──┴──┴──┴──┴──┴──┴──┘      │   │
│   │  键位提示: A S D F G H J K L ; '              │   │
│   └──────────────────────────────────────────────┘   │
│                                                     │
│   当前音名: C4 (261.6 Hz)    最近弹奏: C E G        │
└─────────────────────────────────────────────────────┘
```

**吉他模式**：上方显示 6 根弦（E-A-D-G-B-E），下方 12 个品格区域；每个和弦按钮（C / Am / G / …）对应一组按法，按键 `1–9` 触发不同和弦。

**架子鼓模式**：8 个圆形鼓面/镲片排列（底鼓、军鼓、Hi-Hat、Crash…），每个对应一个键位，按下时鼓面缩放动画 + 采样播放。

### 2.3 交互流程

```
进入演奏模块
    │
    ▼
选择乐器 Tab（钢琴 / 吉他 / 鼓）
    │
    ▼
（钢琴）按字母键 → Tonal.Note 解析音名 → 计算频率 → 发声
              → 对应琴键高亮 200ms → 更新「当前音名」显示
    │
    ▼
（吉他）按数字键 1–9 → Tonal.Chord 获取和弦音组 → 依次/同时播放
              → 和弦图高亮 → 显示和弦名称（如 "Am"）
    │
    ▼
（鼓）按映射键 → 播放对应鼓采样 → 鼓面缩放 + 波纹动画
    │
    ▼
（可选）练习任务：「请弹出 C 大三和弦」→ 检测按键序列 → 反馈正误
```

### 2.4 技术选型

#### 2.4.1 键盘映射方案

| 乐器 | 键位映射 | Tonal.js 用途 |
|------|----------|---------------|
| 钢琴 | `A S D F G H J` = 白键；`W E T Y U` = 黑键 | `Note.midi("C4")` → MIDI → 频率；`Note.transpose("C4", "M2")` 升降 |
| 吉他 | `1–9` = 预设和弦；`Q W E R` = 单音拨弦 | `Chord.get("Am")` → `["A","C","E"]`；`Note.freq()` |
| 架子鼓 | `Z X C V B N M ,` = Kick/Snare/HiHat/Crash… | 不经过 Tonal，直接映射采样 ID |

#### 2.4.2 音源方案对比

| 维度 | Web Audio 振荡器 | WebAudioFont 采样库 |
|------|------------------|---------------------|
| 音质 | 电子味，缺乏泛音 | 接近真实乐器 |
| 体积 | 0 KB 额外加载 | 钢琴 ~1–3 MB，鼓组 ~500 KB |
| 延迟 | 极低（<5ms） | 略高（需 decode 缓冲） |
| 多音同时 | 简单（多个 Oscillator） | 需管理 Voice 池 |
| 适用乐器 | 钢琴（勉强）、音高练习 | 钢琴、吉他、鼓组 |
| 离线可用 | ✅ | ✅（文件内嵌或 CDN） |

**推荐策略**：

- **钢琴练习（音名/音程）**：振荡器即可，与现有 Demo 听音识名一致，零加载
- **吉他和弦 / 架子鼓**：WebAudioFont 采样，体验提升明显
- **混合架构**：封装统一 `AudioEngine.play(instrument, note, velocity)` 接口，内部按乐器路由

#### 2.4.3 视觉反馈

| 反馈类型 | 实现方式 | 复杂度 |
|----------|----------|--------|
| 琴键高亮 | CSS `classList.add("active")` + `transition` | 低 |
| 按键提示 | 键帽下方标注字母，active 时变色 | 低 |
| 鼓面动画 | CSS `transform: scale(0.92)` + `@keyframes ripple` | 低 |
| 吉他品格 | SVG 指板 + 按点圆点高亮 | 中 |

### 2.5 实现复杂度评估

| 子模块 | 复杂度 | 预估工时 | 关键风险 |
|--------|--------|----------|----------|
| 钢琴键盘 + 振荡器 | **低** | 1–2 天 | 黑键布局 CSS 对齐 |
| 钢琴 + WebAudioFont | **中** | 2–3 天 | 采样加载时间、移动端流量 |
| 吉他和弦一键弹 | **中** | 2–3 天 | 和弦指法 UI 设计 |
| 架子鼓 + 采样 | **中** | 2–3 天 | 多采样并发、内存 |
| 统一 AudioEngine 抽象 | **中** | 1–2 天 | 接口设计需预留扩展 |
| 练习任务模式（弹指定和弦） | **高** | 3–5 天 | 输入序列匹配、容错 |

**方向一整体：中**

### 2.6 与现有 Demo 的衔接方式

| 衔接点 | 方式 | 改动范围 |
|--------|------|----------|
| 入口 | 开始页新增第四个 Tab「🎹 演奏练习」，与「综合练习 / 听音识名」并列 | 新增模块，不改现有答题逻辑 |
| 音频引擎 | 抽取现有 `AudioEngine`（振荡器）为共享模块，演奏模块扩展 `playSample()` | 可选重构，非必须 |
| 乐理数据 | 听音识名模式的 `midiToFreq` 可复用；Tonal.js 替代手写音名数组 | 渐进替换 |
| 练习联动 | 「请弹出题目要求的和弦」类题目，判题逻辑调用 Tonal `Interval.distance` / `Chord.detect` | 新增题目类型 `mode: "perform"` |
| 计分/连击 | 演奏练习可独立计分，或作为「bonus 关」不计入主题库 | 配置开关 |

## 3. 方向二：节奏闯关模块

### 3.1 功能目标

参考《节奏大师》**下落式音符**玩法：音符从上方落下，用户在准确时机按键，系统判定 Perfect / Good / Miss，训练节奏感与反应速度。

### 3.2 界面布局草图（文字描述）

```
┌─────────────────────────────────────────────────────┐
│  ♩ 120 BPM    关卡 1/5    ★★☆    得分: 1250        │
├─────────────────────────────────────────────────────┤
│                                                     │
│              ┌───┐                                  │
│              │ ♩ │  ← 下落音符（Canvas 绘制）        │
│              └───┘                                  │
│                    ┌───┐                            │
│                    │ ♪ │                            │
│                    └───┘                            │
│                                                     │
│  ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─  ← 判定线        │
│                                                     │
│  ┌─────┐  ┌─────┐  ┌─────┐  ┌─────┐               │
│  │  D  │  │  F  │  │  J  │  │  K  │  ← 按键轨道    │
│  └─────┘  └─────┘  └─────┘  └─────┘               │
│                                                     │
│  [Perfect!]  ← 判定反馈浮层（居中弹出，0.5s 消失）   │
└─────────────────────────────────────────────────────┘
```

- **4 轨道**（D / F / J / K），对应 4 个按键
- 音符从顶部 Canvas 区域下落到判定线（距底部约 80px）
- 判定反馈：Perfect = 金色光圈；Good = 绿色；Miss = 红色 + 音符穿透

### 3.3 交互流程

```
选择关卡（纯节奏 / 旋律片段）
    │
    ▼
预加载谱面 JSON + 音频（可选伴奏）
    │
    ▼
倒计时 3-2-1 → 启动 requestAnimationFrame 主循环
    │
    ├── 每帧：更新音符 Y 坐标（y += speed × deltaTime）
    ├── 每帧：检测音符是否到达判定窗口
    │
    ▼
用户按键 → 取判定线 ±window 内最近音符
    │
    ├── |Δt| ≤ 50ms  → Perfect (+100 分)
    ├── |Δt| ≤ 120ms → Good    (+50 分)
    └── 无音符 / 超时 → Miss   (连击清零)
    │
    ▼
谱面结束 → 结算：总分 / Perfect 率 / 最高连击 / 评级 S-A-B-C
```

### 3.4 技术选型

#### 3.4.1 谱面数据格式（自制 JSON）

```json
{
  "title": "四分音符入门",
  "bpm": 80,
  "duration": 16,
  "notes": [
    { "time": 0.0,  "lane": 0, "type": "quarter" },
    { "time": 0.5,  "lane": 1, "type": "quarter" },
    { "time": 1.0,  "lane": 0, "type": "eighth" },
    { "time": 1.25, "lane": 2, "type": "eighth" }
  ]
}
```

- `time`：秒（相对歌曲起始）
- `lane`：轨道索引 0–3
- `type`：音符形态（决定 Canvas 绘制样式）

Tonal.js 用途：若采用**旋律片段**模式，可将 MIDI 音高转为谱面（`Note.midi` → 频率 → 播放伴奏），但纯节奏练习可不依赖 Tonal。

#### 3.4.2 渲染方案

| 方案 | 优点 | 缺点 | 推荐 |
|------|------|------|------|
| Canvas 2D | 60fps 流畅，音符量大无压力 | 需自绘 UI | ✅ 主渲染 |
| DOM 元素 | 实现简单 | 音符 >30 时性能差 | 仅用于 HUD |
| CSS Animation | 无 JS 动画代码 | 难以精确同步判定 | ❌ |

#### 3.4.3 判定引擎

```
判定窗口（以判定线时间 T 为基准）：
  Perfect: T - 50ms ~ T + 50ms
  Good:    T - 120ms ~ T + 120ms（排除 Perfect 区）
  Miss:    音符落过判定线 + 120ms 仍未击中
```

- 使用 **Web Audio `currentTime`** 或 **`performance.now()`** 做高精度计时
- 音频驱动 vs 视觉驱动：建议 **视觉 rAF 驱动 + 音频 time 校准**，避免漂移

#### 3.4.4 音频配合

| 模式 | 做法 |
|------|------|
| 纯节奏 | 按键时播放 Click/Clap 采样，无旋律 |
| 旋律片段 | 预录 MP3/OGG 伴奏 + 谱面时间轴对齐；Perfect 时播放对应音高（Tonal + 振荡器） |

### 3.5 实现复杂度评估

| 子模块 | 复杂度 | 预估工时 | 关键风险 |
|--------|--------|----------|----------|
| Canvas 下落 + 判定线 | **中** | 3–4 天 | 时间同步精度 |
| 判定引擎 Perfect/Good/Miss | **中** | 2–3 天 | 输入延迟补偿（不同设备） |
| 谱面 JSON 编辑器（内部工具） | **中** | 2–3 天 | 非必须，可手写 |
| 视觉反馈（光圈/连击/粒子） | **中** | 2–3 天 | 性能优化 |
| 旋律伴奏对齐 | **高** | 4–5 天 | 音频-视觉漂移 |
| 关卡系统 + 星级评定 | **低** | 1–2 天 | — |

**方向二整体：高**

### 3.6 与现有 Demo 的衔接方式

| 衔接点 | 方式 | 改动范围 |
|--------|------|----------|
| 入口 | 开始页新增 Tab「🥁 节奏闯关」，或在「节奏型识别」题目后插入 bonus 关 | 独立模块 |
| 题库关联 | 现有「节奏型识别」6 道题可衍生为 6 个节奏关卡的第一关 | 数据层复用 `type: "节奏型识别"` |
| 连击系统 | 直接复用现有 combo 逻辑（连击 ×2 加分），判定 Perfect 触发 combo++ | 共享 `state.combo` 模式 |
| 难度 | 初级 BPM 60–80 / 中级 80–120 / 高级 120+ 复杂切分 | 映射现有 `difficulty` 字段 |
| 听音反馈 | Miss 播放低沉音、Perfect 播放现有 `playCorrect()` | 复用 AudioEngine |

## 4. 方向三：乐理符号识别模块

### 4.1 功能目标

通过**翻翻乐、卡片配对、拖拽匹配**等轻量游戏，帮助用户建立常见乐理符号的**视觉识别 → 名称 → 含义 → 声音**四重记忆。

### 4.3 交互流程

#### 翻翻乐

```
进入符号识别 → 选择子主题（音符 / 休止符 / 调号 / 力度）
    │
    ▼
生成 8 对卡片（16 张），洗牌排列
    │
    ▼
点击卡片 → CSS flip 动画（0.4s）→ 显示正面（符号）或背面（名称）
    │
    ▼
第二张翻开 → 检测是否配对（symbol.id === name.id）
    │
    ├── 配对成功 → 卡片保持翻开 + 播放声音示例 + 绿色边框
    └── 配对失败 → 0.8s 后翻回

全部配对 → 结算步数/用时 → 星级
```

#### 拖拽匹配

```
显示 N 个符号 + N 个名称槽位
    │
    ▼
拖拽符号到槽位 → dragover 高亮 → drop 检测
    │
    ├── 正确 → 槽位变绿 + 符号固定 + 播放声音 + Tonal 验证（如调号→调名）
    └── 错误 → 弹回 + 红色闪烁

全部正确 → 结算
```

### 4.4 技术选型

#### 4.4.1 符号数据模型

```json
{
  "id": "note-quarter",
  "category": "音符",
  "symbol": "♩",
  "symbolSvg": "<svg>...</svg>",
  "name": "四分音符",
  "meaning": "时值为 1 拍，实心符头带符杆",
  "audio": { "type": "rhythm", "duration": 0.5 },
  "tonal": null
}
```

```json
{
  "id": "key-G-major",
  "category": "调号",
  "symbol": "1♯",
  "name": "G 大调",
  "meaning": "一个升号 F♯",
  "audio": { "type": "scale", "notes": ["G4","A4","B4","C5","D5","E5","F#5","G5"] },
  "tonal": { "key": "G major" }
}
```

Tonal.js 用途：

- `Key.majorKey("G")` → 验证调号-调名配对
- `Note.freq("C4")` → 播放符号对应音高
- `Interval.get("P5")` → 音程符号含义校验

#### 4.4.2 符号渲染

| 符号类型 | 渲染方式 | 说明 |
|----------|----------|------|
| 音符/休止符 | Unicode（♩♪♬𝄽𝄾）或 inline SVG | Unicode 简单但样式受限 |
| 调号 | 自绘 SVG 五线谱 + 升降号 | 需准备 15 种调号 SVG 模板 |
| 力度记号 | SVG / 图片 | pp, p, mp, mf, f, ff, sfz |
| 反复记号 | SVG | 𝄇𝄆 等 |

推荐：**常用符号用 Unicode，复杂符号（调号、五线谱）用预置 SVG 组件**。

#### 4.4.3 声音示例

| 符号 | 播放方式 |
|------|----------|
| 四分音符 | 振荡器 0.5s 单音 C4 |
| 八分音符 | 0.25s × 2 连续 |
| 休止符 | 静默 + 视觉「停顿」动画 |
| 调号 | Tonal `Scale.get("G major")` → 上行音阶 |
| 和弦符号 | Tonal `Chord.get("Cmaj7")` → 琶音 |
| 力度 ff | 高 gain 振荡器 vs pp 低 gain |

#### 4.4.4 交互实现

| 模式 | 核心技术 | 移动端 |
|------|----------|--------|
| 翻翻乐 | CSS `transform: rotateY(180deg)` + `backface-visibility: hidden` | ✅ 点击即可 |
| 拖拽匹配 | HTML5 Drag and Drop API | ⚠️ 需 touch 兼容层（pointer events） |
| 点击配对（备选） | 点击符号 → 点击名称，无需拖拽 | ✅ 更简单 |

## 5. 整体技术可行性总结

### 5.1 可行性矩阵

| 方向 | 技术可行性 | 纯前端 | Tonal.js 价值 | 主要挑战 |
|------|-----------|--------|---------------|----------|
| 键盘演奏 | ✅ 高 | ✅ | 音名/和弦/转调 | 采样加载、多音并发 |
| 节奏闯关 | ✅ 中高 | ✅ | 可选（旋律模式） | 时间同步、输入延迟 |
| 符号识别 | ✅ 高 | ✅ | 调号/音阶/和弦验证 | SVG 素材制作 |

### 5.2 Tonal.js 集成评估

| API | 适用方向 | 示例 |
|-----|----------|------|
| `Note.get / Note.freq / Note.midi` | 演奏、听音、符号 | `Note.freq("A4")` → 440 |
| `Note.transpose / Note.enharmonic` | 演奏（升降） | `transpose("C4", "A1")` → 升降半音 |
| `Interval.get / Interval.distance` | 答题、符号 | 验证音程名称 |
| `Chord.get / Chord.detect` | 演奏、符号、答题 | `detect(["C","E","G"])` → "C major" |
| `Key.majorKey / Key.minorKey` | 符号、调号题 | 调号 → 音阶 |
| `Scale.get` | 符号声音示例 | 播放调号对应音阶 |

- **引入方式**：CDN `<script>` 或 ES Module import，约 20KB gzip
- **与现有 Demo 关系**：现有手写 `NOTE_NAMES`、`midiToFreq` 可逐步迁移至 Tonal，**非必须一次性替换**

### 5.3 性能与兼容性

| 关注点 | 评估 |
|--------|------|
| 移动端 | Web Audio 需用户手势激活（现有 Demo 已处理）；拖拽需 touch 适配 |
| 内存 | WebAudioFont 全乐器 ~10MB，按需加载单乐器 ~1–3MB |
| 帧率 | 节奏模块 Canvas 60fps，单页无压力 |
| 浏览器 | Chrome / Edge / Firefox / Safari 15+ 均支持 Web Audio API |
| 离线 | 全部资源可内嵌或 Service Worker 缓存，满足纯前端 |

### 5.4 推荐实施优先级

```
Phase 1（1–2 周）  方向三：符号识别（翻翻乐）
                   └─ 最快出成果，与现有答题互补，复杂度最低

Phase 2（2–3 周）  方向一：钢琴演奏（振荡器版）
                   └─ 复用 AudioEngine，强化听音识名

Phase 3（2–3 周）  方向一扩展：吉他/鼓 + WebAudioFont
                   └─ 采样加载机制在此阶段建立

Phase 4（3–4 周）  方向二：节奏闯关
                   └─ 复杂度最高，需独立 Canvas 引擎，建议最后
```

## 6. 与现有 Demo 的集成建议

### 6.1 架构建议：多模块 Tab 壳

现有 Demo 为**单页 + 单模块**结构。集成三个方向时，建议采用**「壳 + 模块」**架构，但**不修改现有答题模块代码**，而是：

```
index.html
├── styles/shared.css        ← 公共变量、按钮、卡片
├── js/audio-engine.js       ← 从现有 Demo 抽取（可选）
├── js/quiz-module.js        ← 现有 Demo 逻辑（原样保留）
├── js/perform-module.js     ← 方向一（新增）
├── js/rhythm-module.js      ← 方向二（新增）
├── js/symbol-module.js      ← 方向三（新增）
├── js/tonal-bridge.js       ← Tonal.js 封装（新增）
└── data/
    ├── questions.json       ← 现有 30 题
    ├── symbols.json         ← 符号卡片数据
    └── charts/              ← 节奏谱面
```

通过 Tab 切换显示/隐藏各模块 DOM 区域，**各模块独立 state，互不污染**。

### 6.2 共享能力层

| 共享模块 | 现有 Demo 已有 | 新增方向需要 |
|----------|-------------|-------------|
| AudioEngine | 振荡器 + 正误音效 | + 采样播放 + 多 Voice 管理 |
| 计分/连击 | score / combo / maxCombo | 直接复用模式 |
| 难度 | difficulty 1/2/3 | 各模块自行映射 |
| Tonal.js | 未引入 | 统一在 tonal-bridge 封装 |

### 6.3 数据流关系

```
                    ┌─────────────┐
                    │  Tonal.js   │
                    └──────┬──────┘
                           │
         ┌─────────────────┼─────────────────┐
         ▼                 ▼                 ▼
  ┌─────────────┐  ┌─────────────┐  ┌─────────────┐
  │  综合练习    │  │  听音识名    │  │  符号识别    │
  │ (文字题库)   │  │ (MIDI 播放)  │  │ (SVG+声音)  │
  └──────┬──────┘  └──────┬──────┘  └──────┬──────┘
         │                │                │
         └────────────────┼────────────────┘
                          ▼
                  ┌─────────────┐
                  │ AudioEngine │
                  └──────┬──────┘
                         │
              ┌──────────┼──────────┐
              ▼          ▼          ▼
        ┌──────────┐ ┌────────┐ ┌────────┐
        │ 演奏练习  │ │节奏闯关 │ │ (共用) │
        └──────────┘ └────────┘ └────────┘
```

### 6.4 集成原则

1. **现有 Demo 代码零修改**：新功能以 sibling 模块文件追加
2. **AudioEngine 只扩展不破坏**：新增 `playSample()`、`playScale()` 方法，现有 `playNote/playCorrect/playWrong` 签名不变
3. **Tonal.js 渐进引入**：新模块先用 Tonal，旧模块保持手写逻辑，后续按需迁移
4. **统一入口 UI**：开始页 Tab 从 2 个扩展至 5 个（综合 / 听音 / 演奏 / 节奏 / 符号）
5. **独立计分或统一排行榜**：建议各模块独立结算，主页展示「最近成绩摘要」

### 6.5 风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| 单文件膨胀 | 维护困难 | 拆分为多 JS 文件，`type="module"` 加载 |
| 采样体积大 | 首屏慢 | 按乐器懒加载；演奏模块内嵌振荡器兜底 |
| 节奏同步漂移 | 判定不准 | 以音频时间为权威，视觉做插值 |
| 符号 SVG 版权 | 法律风险 | 自绘或使用 SMuFL 开源字体（如 Bravura） |
| 键盘映射冲突 | 演奏 vs 答题 | 模块切换时 `removeEventListener` 卸载按键监听 |
