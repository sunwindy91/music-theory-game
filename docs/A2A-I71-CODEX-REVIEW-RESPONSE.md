## verdict: 通过（3 条微调）

方向完全正确——左摇右技、InputAdapter 双层、分期 C→D。三条调整：

1. 右开火簇的「切弹」不应跟「开火」穿一条裤子——切弹是低频操作，放右上角独立小钮更好，拇指主要区域留给开火（大）+闪避（中下）。
2. 「点画面开火」在 MOBA 布局下应**全量禁用**，不是「并存但右钮为主」。并存必有误触——手指滑动摇杆时拇指根很容易蹭到画面。
3. 横屏锁必须处理 iOS Safari 的地址栏/底部 bar 侵入——ullscreen API 是必需品不是可选品。

## Q1 分区是否够用？

够用。左摇杆 + 右三钮已满双手拇指覆盖区。不要再往右区加第四个按钮。当前开火/闪避/撞击 + 顶栏切弹 = 恰好是单手拇指可覆盖的极限。

缺一个东西但不在布局层面：**摇杆死区**。中心 15-20px 范围内不触发移动——防止拇指微颤导致机体抖动。

---

## Q2 强制横屏 vs 提示旋转？

**推荐：提示旋转 + 竖屏内一个「旋转进入」按钮。** 强制横屏有两个坑：

- iOS Safari 的 screen.orientation.lock("landscape") 在非全屏模式下不稳定，部分版本静默失败。
- 用户可能在竖屏状态点进星图只是为了看星区地图——不该在地图界面就锁横屏。

做法：竖屏进星图 → 显示提示层「旋转手机体验更好」+ [进入横屏] 按钮。点按钮或用户主动旋转 → 切横屏并锁定。地图/整备界面保持竖屏可用。

---

## Q3 「点画面开火」与右开火钮如何并存？

**不要并存。MOBA 模式下禁用点画面开火。** 手指在右区按键时，拇指根和大鱼际会误触画面。用户右手拇指只有一个——要么在按钮上、要么在画面上，不存在「同时用两个」。

实现：InputAdapter.touchMOBA 初始化时 preventDefault 掉画布的 	ouchstart 事件，右区按钮用自己的 listener 接管。PC 键盘模式下保留空格开火。

## Q4 MVP 最小切片

**MVP1：横屏 + 左摇杆移动（1 天）**
- `InputAdapter` 骨架：detect 设备类型 → keyboard | touchMOBA
- 手机进入星图战役：显示旋转提示 + `[进入横屏]` 按钮
- 横屏后左摇杆 80px 圆形，产 `{vx, vy}` 映射到现有移动逻辑
- 开火暂用老方式（点画面），摇杆用 alpha 透明白底快速验证
- 验收：手机横屏后能用摇杆移动机体

**MVP2：右开火簇 + 禁用点画面（1-2 天）**
- 右区：开火（大圆，右下）+ 闪避（中圆，开火下方）
- MOBA 模式禁用点画面开火
- 切弹移到顶栏右侧（独立小钮）
- 按钮半透明 0.6 alpha，手指按下→0.9
- 验收：手机纯用按钮完成完整一局远征

**后置**：撞击按钮、陀螺仪、摇杆死区精调、横屏 UI 缩放适配——等问卷后迭代。

## Q5 是否需要陀螺仪/多指手势？

**默认不要。** 三条理由：
1. 问卷还没说用户需要——先把"有没有方向键"解决了，再谈微操
2. 多指手势跟摇杆+按钮打架——左手拇指在摇杆、右手在开火，哪根手指做双指缩放？
3. MVP 里加陀螺仪 = 延迟 3 天。当下目标是"能玩"，不是"玩得跟 PC 一样丝滑"

## 风险清单

| 风险 | 等级 | 缓解 |
|------|------|------|
| iOS Safari orientation.lock 静默失败 | **高** | 不依赖 API lock——CSS @media + 旋转提示按钮双重兜底 |
| 摇杆延迟 >50ms 导致漂移 | 中 | 用 requestAnimationFrame 驱动摇杆更新 |
| 右开火钮被 Boss telegraph 覆盖 | 中 | 开火钮 position:fixed，不随 Canvas 偏移 |
| 横屏后 UI 元素太小 | 中 | MVP2 加 Canvas scale 适配（0.85-0.9） |
| 安卓软导航栏占横屏底部 | 低 | viewport meta 加 viewport-fit=cover |
| 点画面开火切换逻辑遗漏 | 中 | InputAdapter 必须含 mode 字段——切换 MOBA 时 canvasTouchEnabled=false |
