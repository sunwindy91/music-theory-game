# 文化引用 → 玩法拆解（给 Agent / 未来的你）

> **用途**：你用「我玩过的游戏 / 看过的作品」形容手感时，Agent 按本表拆成可实现的系统字段，而不是空泛模仿。  
> **不是**：去 GitHub 扒源码、爬站抓全集（通常无必要且有版权风险）。  
> **是**：你点名作品 + 想要的手感 → 映射到我们星图的规则语言。

## 你怎么提需求（推荐句式）

> 「像《作品》里的【角色/系统】那样：【1 句手感】。落到咱们游戏里，大概是【弹药/叠层/撞击/…】。」

例：海克斯叠角龙 → 正确击杀计数 → 10/20 阶进化体型与撞击。

## 拆解模板（Agent 每次用）

| 字段 | 填什么 |
|------|--------|
| 来源 | 作品名 + 机制昵称 |
| 玩家爽点 | 一句话（变强可见 / 选对有奖 / 肉搏反击…） |
| 乐理挂钩 | 必须能连到大三/小三/音名等，否则降级为纯玩法皮肤 |
| 系统字段 | 计数器、阈值、体型倍率、碰撞伤害、UI 提示 |
| 切片 | MVP 只做 1 个阈值 + 1 个体型档，再扩展 |

## 要不要专门的 GitHub Skill / 爬取工具？

**短期：不需要。**  
原因：你已经能说出作品名和手感；缺的是「落成系统字段」，不是缺一部剧的剧本全文。

**值得做的（已部分具备）**

1. 本文件 + `IDEA-BACKLOG`：引用词典  
2. 项目 Skill：要求 Agent 用上表拆解  
3. 你本地若开浏览器，Agent 可用网页查「机制 wiki 摘要」（官方/社区 wiki），**只取机制描述，不扒资源包**

**以后才考虑**

- 个人 Skill「pop-culture → game mechanic」：固定拆解输出格式  
- 自己维护一份「手感词典」Notion/md（比爬虫稳）

## 这是机器学习吗？

**不是在训练神经网络。**

| 概念 | 我们在做什么 |
|------|----------------|
| 模型微调 / ML 训练 | ❌ 没有在改权重、没有数据集梯度下降 |
| 人机协作的设计迭代 | ✅ 体验 → 想法 → 切片 → 验收 → 再想法 |
| 外化记忆（Skill/Backlog） | ✅ 让下一次对话更强，像「给 Agent 装手册」 |
| 世界观架构 | ✅ 把多作品精华收成**同一套规则语言**（弹药·抗性·叠层·角色） |

所以更准确的说法是：

> **世界观架构 + 可复用的设计本体（ontology）+ Agent 飞轮**，  
> 目的是让你和 AI **一起越来越厉害**；  
> 若将来真做模型训练，那是长远层，和现在写星图规则是两件事。

把「看过的、玩过的」炼成咱们宇宙里的一条条规则——这本身就是创作，不是空话。
