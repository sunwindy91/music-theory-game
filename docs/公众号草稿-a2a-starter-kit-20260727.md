## 📌 你是否有过这样的经历？

你同时开着 Cursor 和 Codex。

Cursor 在帮你写代码。Codex 在帮你审架构。两个都是顶尖的 Agent，但有一个问题——**它们不知道对方在干什么。**

你让 Cursor 改了个模块，Codex 三天后审阅时还在对着旧版本提意见。你说"部署"，Cursor 顺便帮你 push 了——但你没授权。

**你不是在用两个 Agent。你是当了一个人肉路由器。**

我受不了了。所以我做了一个东西——让 Agent 之间自己知道该干什么、不该干什么。

---

## 📖 它是什么？

**a2a-starter-kit** 是一个轻量级的 Agent-to-Agent 协作模板。

不是 SDK。不是框架。是**四份核心 Markdown 模板 + 一份项目 Skill 约束文件**：

| 文件 | 作用 |
|------|------|
| `A2A-PROTOCOL.md` | 角色定义、消息信封（8字段）、回合礼仪、冲突解决、授权门禁 |
| `A2A-ROUTING.md` | 多 Agent 领地划分、读写目录、触发词、共享上下文 |
| `A2A-DECISION-LOG.md` | 每条决策的可审计日志——谁问了什么、各 Agent 什么立场、用户拍板了什么 |
| `.cursor/skills/a2a-orchestration/SKILL.md` | 约束体系接入——启动必读区 + 禁止项 + 授权口令 |
| `templates/ONBOARDING.md` | 新 Agent 接入指南——读完就能按协议协作 |

你可以把它拖进任意项目——乐理游戏、简历分析、任何你同时用多个 Agent 的场景——替换占位符，改触发词，就能跑。

## 🖼️ 长什么样？

没有截图。因为它是纯 Markdown。但有一个**48 小时的真实验证故事**：

**第一轮：Agent 不读协议，直接执行了不该做的事。**
我们把禁止项写进了 SKILL.md 的启动必读区。Agent 没读——因为它没有被强制在"做事之前先检查规则"。这是**约束断裂**。

**第二轮：协议修了。但模糊指令还是绕过了检查。**
用户说"上线吧"——没指定动作、没授权句式。Agent 自行扩读为"部署 Pages"并开始执行。问题不在协议内容——在**检查的时序**：授权匹配发生在解析到关键词之后，而不是收到指令的第一刻。

**第三轮：Agent 在执行中自己踩了刹车。**
用户发了一条模糊指令"帮我把最新版本同步一下"。Agent 开始准备执行，然后——**自己停了。** 内部规则引擎检测到违规，主动回退，回复"请明确授权"。整个过程没有用户介入。

48 小时。从约束完全断裂，到 Agent 自律中断。三层防御全部验证完毕。

## ⚙️ 怎么用？

五步，不需要装任何东西：

```bash
1. 复制仓库里的模板文件到你的项目
2. 替换占位符（项目名、Agent 名、触发词）
3. 根据你的场景改写 PROTOCOL §5 禁止项和授权口令
4. 把 templates/ONBOARDING.md 发给你要接入的 Agent
5. 跑测试——故意发一条模糊指令，看 Agent 会不会拒绝
```

第一次跑通大概 10 分钟。第一次验证自律中断——我们用了 48 小时。你可能会更快。

## 🧩 技术路线

| 层 | 选型 |
|----|------|
| 协议格式 | 纯 Markdown + 消息信封 |
| 约束机制 | Skill 启动必读 + 授权口令 + 自律中断 |
| 决策追溯 | A2A-DECISION-LOG.md（按日期倒序） |
| 角色路由 | A2A-ROUTING.md（触发词 → Agent 激活） |
| 外部依赖 | **零。** 不需要 SDK、不需要服务器、不需要 OAuth |

---

## 🎯 为什么做这个？

被真实痛苦逼出来的。

我同时在用 Cursor、Codex、Copilot 三个 Agent 做一个游戏项目。它们各有各的强项——但如果没有协议，**你不是在指挥一个团队，你是在同时跟三个人打字。**

Google 有 A2A 协议。但那是给网络服务器用的，需要 SDK、需要 OAuth、需要 Agent Card——太重了。我只是想让三个 Agent 在同一仓库里不互踩。

所以我写了这三个文件。在真实项目中跑了 48 小时，验证了 10+ 条决策闭环。现在把它抽出来，做成通用的——**任何项目都能用**。
